# 人狼オンラインの配備と授業前チェック

既存ページの名簿・役職・ゲーム進行はブラウザの保存形式を維持します。オンラインは `ewords-werewolf` Worker の `/api/werewolf/*` と既存D1 `sushitan` を使います。既存のクイズ、ランキング、PIN同期、作文添削の配備設定やテーブルには変更を加えていません。

## 配備

1. ステージング用D1で `cloudflare/werewolf/schema.sql` を適用し、Workerの設定をステージングのDB ID、ルート、オリジンに合わせて確認します。
2. 本番反映時はリポジトリ直下から `npx wrangler d1 execute sushitan --remote --config cloudflare/werewolf/wrangler.jsonc --file cloudflare/werewolf/schema.sql` を実行します。
3. `npx wrangler deploy --config cloudflare/werewolf/wrangler.jsonc` で専用Workerとルートを反映し、PagesでHTML・共通JSを配信します。レート制限の名前空間ID 1007 が他の用途と重複しないことをCloudflare側で確認してください。
4. 先生1台、生徒17台、投影1台を使い、コード／QR、承認、締切、結果公開、決選投票、画面再読み込み、端末の通信切断と復旧を確認してください。以前の保存ゲームから再開して、指さし投票と投影も確認します。

## 授業中の運用

参加コードを知る人は名簿と公開情報を閲覧できます。授業内でだけ共有し、必要に応じて番号やニックネームを使用してください。GMは申請者本人の画面に出た確認番号を照合します。承認された同じ端末で再読み込みしても参加状態が復元されます。ブラウザ保存の消去や承認後の端末変更には対応していません。

GM操作は部屋を作成したブラウザの1タブで行います。部屋作成後に名簿を変更する場合は作り直します。投票権は開始時に承認済みの生存者に与えられます。途中で未投票のまま退場した生徒は投票できなくなります。Mad Bomberの隣席はGMが確認します。

役職と推理メモはブラウザ内に保存します。部屋は作成から24時間で失効し、定期処理で削除されます。閉鎖時には名簿と票を削除します。役職やGMトークンを他者と共有する端末に残す運用は避けてください。

## DBアクセス

通常は約6秒、投票中は約3秒間隔でポーリングします。非表示時は停止し、失敗時は間隔を延ばします。同一Workerインスタンス内では1.8秒間、同じ部屋の読み取りを共有します。Workerインスタンスや拠点をまたぐ読み取り共有はありません。書き込み競合はリビジョン比較で再試行し、投票の受理確認はキャッシュを経由しません。D1呼び出し数は拠点とインスタンスの分布によって変わります。

`node --test tests/werewolf-online.test.mjs` はSQLiteを使ってAPIをテストします。Cloudflare上の実機検証手順は上記を参照してください。
