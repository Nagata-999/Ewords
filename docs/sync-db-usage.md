# 同期DB処理の削減

本番Worker `ewords` の 2026-11-06 公開アセットを取得して修正しています。`shared/sushi-profile.js` のmainソースは本番とは異なる旧版です。本番はWorker内の `pin-auth-poc/assets/profile.txt` と `bridge.txt` から配信されます。このPRの同名アセットは本番用の保存版であり、Worker設定全体を上書きするものではありません。

- 自動同期を30秒単位にまとめ、Web Locks対応ブラウザではタブ間でも重複を防止します。
- 変更がないページ遷移では直近5分以内の自動同期を省略します。
- 非表示・オフライン時は休止します。未同期フラグと元の記録は残し、復帰時に再試行します。
- 明示的なウォレット同期・手動同期・報酬請求は待機させません。
- 実績の独立した自動同期タイマーをプロフィール側へ集約します。
- 実績の受領確認をアカウント別に保存し、同じ内容の再送を省きます。失敗・不正応答では未確認のデータを除外しません。
- 実績が変わっていない場合の再取得と、報酬受領一覧の再取得は5分間省略します。
- 通常の学習履歴は既存の手動同期方針を維持します。サーバーの削除・スキーマ変更はありません。

本番反映はPagesの `sushigacha/achievement-transport.js` とWorkerの上記2アセットを更新します。旧transportは追加オプションを無視するため切り替え中も従来方式で動作します。トランスポートだけ先行しても追加オプションなしでは従来方式です。

検証: `node --test tests/sync-db-usage.cjs`。連続60イベントの自動同期2回、停止・復帰、失敗後の保持、受領確認、複数アカウント、全ページ取得、強制更新を確認。
