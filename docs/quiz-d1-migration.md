# すしクイズのD1接続

クイズ専用Worker `ewords-quiz` から既存D1 `sushitan`（binding `DB`）を利用します。ランキング・PIN同期の既存Worker `ewords` は変更しません。

## 反映順序

1. `ewords-quiz` のみを変更対象にします。既存 `ewords` の本番コードは保存版PR #92より新しいため、保存版で上書きしません。
2. `cloudflare/quiz/schema.sql` をD1に適用します。既存ランキング・PINテーブルは変更しません。
3. `cloudflare/quiz/wrangler.jsonc` で専用Workerをデプロイします。管理画面の場合は `worker.mjs` を配置し、D1 binding `DB=sushitan`、変数 `QUIZ_READY=true`、レート制限 `QUIZ_LIMIT`（namespace 1003、120回/60秒）、ルート `sushitan.net/api/quiz/*` を設定します。
4. クイズHTML2枚と `shared/quiz-d1.js` を配信します。ランキングは既存 `/api/rankings/` を使用します。
5. 通常対戦と早押しで作成・別タブ参加・回答・次の問題を確認します。ランキング・PIN同期も確認します。

部屋は新DBで新規作成します。旧Supabaseの一時的な対戦部屋はコピーせず、旧DBは削除しません。6桁の部屋番号、有効期限24時間、最大100人です。期限切れデータの物理削除はこの変更に含みません。

部屋ごとのホスト・参加者トークンはタブ単位のsessionStorageに保管します。共通アカウントやPIN同期の認証状態は変更しません。部屋番号だけで問題変更や他人の回答変更はできません。

1秒間隔で状態を取得し、同一周期の部屋・参加者取得をまとめます。前の通信完了後に次の取得を予約します。通常対戦の得点更新は一括トランザクション、早押しの先着判定と加点もトランザクションです。

## 検証

`node --test tests/quiz-d1.test.mjs`。SQLiteによるD1インターフェース検証、通常回答、先着競合、不正解の再回答制限、権限、期限切れ、トランザクション失敗、クライアントの接続先と取得回数、両HTMLの構文を確認します。

ローカルテストの成功は本番反映の完了を意味しません。本番での作成・参加確認を別途行います。
